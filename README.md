# Audit Dashboard

Современная фронтенд-панель (Dashboard) для внутреннего аудита и контроля комплаенса. Система предназначена для управления актами проверок, мониторинга статусов нарушений, оценки уровней риска и сквозной аналитики в реальном времени.

## Стек технологий

*   **Фреймворк:** React 18+ (TypeScript) с использованием сборщика Vite.
*   **Управление стейтом:** Redux Toolkit. Первичная инициализация и управление сущностями реализованы на базе `createEntityAdapter` (`issuesSlice`) для оптимизации работы с большими массивами данных.
*   **Стилизация:** Tailwind CSS. Вся адаптивность интерфейса построена на чистом синтаксисе **Mobile First** (`md:`, `lg:`), что гарантирует гибкость и чистоту кода.
*   **Локализация:** `i18next` для мультиязычной поддержки интерфейса.
*   **Работа с датами:** Библиотека `date-fns` как современный, иммутабельный стандарт с отличным Tree Shaking.

## 🏗 Ключевые архитектурные решения (MVP)

1. **Паттерн "Lifting State Up":** Загрузка данных из Redux-стора (`useSelector`) и управление глобальными фильтрами подняты на уровень страницы-контейнера `Dashboard.tsx`. Данные распределяются вниз в дочерние компоненты (`Analytics`, `Filters`, `Table`) строго через однонаправленные props.
2. **Контролируемые UI-компоненты:** Кастомные элементы выпадающих списков (мультиселекты) переведены на полностью контролируемые рельсы. Они не хранят внутренний стейт данных, а оперируют пропсом `value` и возвращают иммутабельные массивы через `onChange`.
3. **Универсальные Generics в TS:** Компоненты фильтрации спроектированы как Generic-компоненты (`<T extends string>`), что позволяет безопасно переиспользовать один и тот же компонент для фильтрации обычных строк (ССП, года) и строковых энумов (`Statuses`, `RiskLevels`).
4. **Динамический расчет статусов:** В системе не хранится жесткое поле `status` в базе данных или моках. Статус является реактивным и вычисляемым «на лету» значением на основе сравнения плановых и фактических дат проверок с текущей датой (`new Date()`).
5. **Контроль модальных окон:** Спроектирован единый строковый стейт на уровне Dashboard для предотвращения одновременного открытия окон. Вложенные элементы отправляют наверх только триггер или ID сущности.

## 🎛 Функционал панели фильтрации

Панель фильтров поддерживает комбинированную сквозную фильтрацию по всем ключевым параметрам:
*   **Глобальный поиск (Global Search):** Инпут на всю ширину экрана для поиска текстовых совпадений по нескольким колонкам одновременно с функцией мгновенной очистки.
*   **Кастомные Мультиселекты:** Выпадающие списки для выбора проверок, ССП (отделов) и годов.
*   **Табы-переключатели (Тогглы):** Быстрый выбор статусов (`В работе`, `Просрочено`, `Исполнено`, `Снято`) и уровней риска (`Низкий`, `Средний`, `Высокий`).
*   **Концепция «Все»:** Пустой массив `[]` в стейте фильтра семантически означает, что фильтр не активен (выбраны «Все» элементы). При ручном выборе пользователем всех доступных табов система автоматически сбрасывает стейт в `[]` для оптимизации производительности фильтрации.
